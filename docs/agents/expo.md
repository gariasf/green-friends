# Expo / React Native

Green Friends is an Expo (CNG) app: `app/` holds expo-router routes, `src/core` the plain-TypeScript domain, `src/db` the Drizzle schema, migrations and the expo-sqlite handle, `src/ui` shared components, `scripts/` build-time tooling, TypeScript run directly by Node 24 or later (`engines` in `package.json`). See ADR-0001.

## Expo has changed — do not trust your training data

Expo ships breaking changes every SDK release. Before writing code that touches an Expo, EAS, or React Native API:

1. Read the major version of the `expo` package in `package.json`.
2. Fetch the matching versioned docs: `https://docs.expo.dev/versions/v<major>.0.0/`
3. For anything else, fetch https://docs.expo.dev/llms.txt — an index of all Expo docs with corrections to common misconceptions. Follow its links; never answer from memory.

## Commands

```bash
npx expo install <package>   # ALWAYS use instead of npm add — resolves SDK-compatible versions
npm test                     # jest-expo: core seam tests against in-memory SQLite
npm run lint                 # eslint (expo config) + prettier
npm run typecheck            # tsc --noEmit
npm run db:generate          # drizzle-kit: regenerate drizzle/ after editing src/db/schema.ts
npm run species:build        # regenerate assets/species.json and assets/species-index.json from scripts/species/curated.json (queries Wikidata and GBIF)
npm run species:coverage     # Open Plantbook coverage spot-check; reads OPENPLANTBOOK_CLIENT_ID / _SECRET from .env.local (git-ignored)
npm run ios                  # local dev build on the simulator (npx expo run:ios)
npx expo-doctor              # diagnose dependency and config issues
```

Run test, lint and typecheck before declaring any task done.

## House rules

- `src/core` never imports React, React Native, Expo, or `src/db/client` (enforced by eslint). Core functions take the `Db` handle as their first argument; tests hand them an in-memory database via `src/test/db.ts`.
- Every write goes through a `src/core` mutation function; components never call `db.insert/update/delete`. Screens that must react to writes read again through `useAfterWrites` (`src/ui/useAfterWrites.ts`), expo-sqlite's `addDatabaseChangeListener` debounced because it fires once per changed row. Each spans several tables (Today over `evaluateCare`, the Plant screen, the Garden and the archived view over plants and their photos), which Drizzle's `useLiveQuery` would miss: it re-runs on changes to its query's primary table only; Today, the Plant screen and the Daily Digests are also read or planned again when the app returns to the foreground and at local midnight, where the day turns (`useAfterWritesOrForeground`, same file).
- Side effects outside the database go through a small adapter the core function takes after `Db` (spec #8, Testing Decisions); tests pass a fake. The first is `PhotoFiles` (`src/core/photos.ts`), implemented by `photoFiles` in `src/ui/Photo.tsx` over `Documents/photos/`. The database stores a photo's filename only, since the app container's absolute path moves between installs; `photoUri` resolves it at render time. `PendingNotifications` (`src/core/digest.ts`) replaces the pending Daily Digests and remembers the soonest, or today's once shown, in `Documents/digest.json` (the phone's own, never in an Export), so a digest time moved later never shows today's twice; `src/ui/useDigests.ts` implements it over expo-notifications and, from the root layout, plans them again at launch, after every burst of writes and on returning to the foreground, so no mutation has to remember to. `ShareSheet` (`src/core/export.ts`) takes an Export's zip, which the core builds in memory with fflate (`buildExport`, which Sync uploads too; plain JavaScript, so seam tests open the very zip that would be shared) from photo files read through `PhotoFiles`; the Settings tab (`app/(tabs)/settings/index.tsx`) implements it over expo-sharing. Import (`importExport`, `src/core/import.ts`) takes the picked zip's bytes, writes its photos through `PhotoFiles.write`, and takes a second, empty database to bring the Export's rows up to the current schema in: `withScratchDb` (`src/db/client.ts`) opens one in memory, tests pass `emptyDb()` (`src/test/db.ts`). The document picker is expo-file-system's `File.pickFileAsync`, not expo-document-picker.
- The app goes online for two things only: Sync, and Identify from photo (ADR-0007, spec #44; hidden in New plant since 2026-09-27 by `IDENTIFY_SHOWN` in `app/plants/new.tsx`), which sends the prepared photo on the user's tap, and never otherwise, through the relay's `POST /identify` on to Pl@ntNet; `src/ui/useIdentify.ts` implements core's `IdentifyRelay` (`src/core/identify.ts`) over `fetch`, shrinks the photo to 1280 px with `prepare` (`src/ui/Photo.tsx`) and maps Pl@ntNet's candidates to Suggestions through `suggestSpecies` and the bundled name index. In Sync (ADR-0006, spec #35), `createSync` (`src/core/sync.ts`) owns when to upload and the 25 MB Snapshot cap, over a `SyncRelay` adapter; `src/ui/useSync.ts` implements it over `fetch` to the relay at `RELAY_URL` (core's, which the Web view reads from too; docs/agents/relay.md), seals each Export with expo-crypto (`aesEncryptAsync`, whose combined form is the Snapshot's `iv | ciphertext | tag`), and runs from the root layout after every burst of writes, at launch and back in the foreground, doing nothing while Sync is off. The key derivation (`deriveSyncKeys`) is core's, taking a SHA-256 function, so the Web view (`web/`, docs/agents/web.md) derives the same ids through WebCrypto; `src/test/snapshot-fixture.json`, sealed by WebCrypto, pins it. The key lives in expo-secure-store with `AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY`, so it survives a reinstall but never leaves the device; Sync's status (on, Last synced, the last problem, unsynced writes) is `Documents/sync.json`, gone with the app and never in an Export, and a file so that writing it fires no database change; iCloud restores it without the key, so a status without a key loads as off. Hermes has no WebCrypto, so crypto in the app is expo-crypto's, never `crypto.subtle`. Restore from sync (`sync.days`, `sync.restore`) downloads a day's Snapshot, opens it (`AESSealedData.fromCombined`) and runs `importExport`, so a restore is an Import. Reset sync (`sync.reset`) queues behind any upload, `DELETE`s the garden, and only then keeps a new key. A Pairing link opened on the phone is `greenfriends://pair#k=…` (the Web view's Open in Green Friends): `useSync` takes it from expo-linking (`getInitialURL` and the `url` event), and `app/+native-intent.tsx` keeps it off the router, which has no such route. Pairing (`sync.pair`) keeps the key behind any upload, offers an empty Garden the latest Snapshot and turns Sync on without uploading it, so a declined restore never replaces today's Snapshot; `useSync` asks first when the phone already has a different key. Test it on a simulator with `simctl openurl`; its "Open in Green Friends?" prompt and the app's alerts need real taps (an XCUITest runner), since they are native.
- Row ids come from the standard `crypto.randomUUID()` inside core. Hermes has no WebCrypto, so `app/_layout.tsx` installs Expo's native generator at boot; never import `expo-*` into core for ids.
- Care Events are dated by local calendar day, `occurred_on` as `'YYYY-MM-DD'` (ADR-0005). Use `localDay` / `shiftDays` from `src/core/dates.ts` (and `localNoon` where an API takes an instant, such as a date picker), never `toISOString().slice(0, 10)`. Tests run under `TZ=Pacific/Auckland` (jest `globalSetup`, `src/test/timezone.js`) so a day computed through UTC fails; build test dates with the local `Date` constructor when the day matters. Hermes reads a local time in a past year at today's offset, while iOS and `Intl` use that year's: under `Europe/Istanbul` (+2 in 2000, +3 now), `new Date(2000, 0, 1, 9)` is 06:00Z, which a SwiftUI picker shows as 08:00. So a Date handed to native code or `Intl` is never a local time in a past year: Settings' Digest time picker keeps to UTC (`environment('timeZone', 'UTC')`), its month names come from each month's 15th, and `localNoon` stays safe for recent days, since an hour either side of noon is still the same day. Check with `SIMCTL_CHILD_TZ=Europe/Istanbul xcrun simctl launch …`.
- Due-ness is never stored. `evaluateCare` / `listNeedsAttention` in `src/core/care.ts` derive it on every call from the Care Log, the effective schedule (ADR-0003) and the Season settings; they take `today` as a local calendar day, which tests pass explicitly. Both go through `forecastCare`, which reads the database once and evaluates any day; the Daily Digest planner (`planDigests`, `src/core/digest.ts`) asks it day after day.
- Adding a route: after creating the file under `app/`, regenerate the typed-routes declaration (`npx expo customize tsconfig.json`, or start the dev server once) or `npm run typecheck` rejects the new `href`.
- Navigation (spec #22): `app/(tabs)/_layout.tsx` is iOS's tab bar (`NativeTabs` from `expo-router/unstable-native-tabs`, SDK 57) over Today, Garden and Settings, each tab a Stack of its own under a large title. Everything else (a Plant screen, its sheets, Edit plant, Archived, New plant) lives in the root Stack above the tabs, whose back buttons are chevrons only (`headerBackButtonDisplayMode: 'minimal'`); otherwise a screen over the tabs is labelled "(tabs)". A Plant screen with a photo (spec #61, ticket #64) starts it at the screen's top edge: `headerTransparent`, the ScrollView's `contentInsetAdjustmentBehavior="never"` and its bottom padded by the safe area; the bar stays transparent and its `headerBackground`, an `Animated.View` in `background`, fades in over the last 48 pt of the photo from `useScrollOffset`, while `onScroll` gives the bar the plant's name once `contentOffset.y` passes the photo's height less `insets.top` and the bar's 44 pt; the photo drifts at half speed as it scrolls up and stretches from its foot when pulled down (`heroDrift`, `heroStretch` in `src/ui/motion.tsx`). The name over the photo is a sibling of the photo's Pressable, not its child, so VoiceOver reads it as the header apart from Replace photo; it takes touches (no `pointerEvents="none"`), or the accessibility audit flags it as inaccessible text. A plant without a photo keeps the ordinary opaque bar. A tab's screen is a ScrollView first of all, with `contentInsetAdjustmentBehavior="automatic"`, so the large title collapses as it scrolls and a tap on the tab scrolls back up (NativeTabs' scroll-to-top doesn't work with FlatList). Settings is `@expo/ui`'s SwiftUI `Form` instead, in a `Host` filling the screen: UIKit and react-native-screens find a scroll view down the chain of first subviews, and there they reach the Form's collection view as they reach a ScrollView's (checked with lldb on #28), so its large title and scroll-to-top work the same. NativeTabs gives each tab a `SafeAreaProvider` of its own, so inside a tab `useSafeAreaInsets().bottom` already clears the tab bar.
- Sheets (the log sheet, a Care Event's edit sheet) are routes presented with the shared `SHEET` options in `app/_layout.tsx`: a native `formSheet` sized to its content, with a grabber, opaque because the iOS 26 glass default turns dark under the dimmed screen. Each is titled with the plant's name, its task beneath it ("Log care", or the Care Event's type), and carries a `CloseButton` (`src/ui/Form.tsx`; spec #92). A screen pushed from a sheet lands beneath it, so a sheet moves on with `router.replace`. Its content is a `SheetBody` (same file): a ScrollView capped at the window's height less the safe areas, so the sheet still fits its content and, at the largest text sizes, scrolls and clears the keyboard (#90). react-native-screens sizes a `fitToContents` sheet from its children, so a scrolling one needs that `maxHeight`, never `flex: 1`.
- Forms (spec #22): every text input is a `Field` (`src/ui/Form.tsx`): its label above it (for a search field, the heading over it), never a placeholder in its place; its unit a `suffix`; a Done bar on number pads. New plant's Add sits in its header, greyed until the plant can be added, and the form's first line says why; Edit plant is a modal like it, its Save greyed until something changes (spec #92). A plant's care schedule is edited through `useCareSchedule` (`src/ui/CareSchedule.tsx`), which Edit plant and New plant share; so do their Species pickers (`SpeciesSearch`, `src/ui/SpeciesPicker.tsx`), whose search ranks in core (`searchSpecies`, `src/core/species.ts`) and, where no Species' own name matches, falls back to the names in Identify's name index (`otherNames`: former scientific names and second common names, so "Sansevieria" finds the snake plant, #98). Numbers are checked in the form, in its own words (`wholeNumber`, `potSizeProblem`, `useCareSchedule`'s `problem`), before the core, whose messages are written for developers. A form with changes asks before it goes (#90): `useConfirmDiscard` (`src/ui/Form.tsx`) over `usePreventRemove`, imported from `expo-router/react-navigation` in SDK 57, which also holds back a sheet's or a modal's swipe (react-native-screens' `preventNativeDismiss`) and a pushed screen's back swipe. It returns `leave`, which a form calls once its work is saved; a plain `router.back()` after a save would be asked about too.
- Every "when did it happen" is a `WhenPicker` (`src/ui/Form.tsx`): Today, Yesterday and Earlier… chips, and `@expo/ui`'s SwiftUI `DatePicker` in its compact style behind Earlier… (spec #84), since it writes the date in the device region's format ("28 Sep 2026"), which SwiftUI's `locale` environment doesn't change. Earlier… picks two days ago, the first day neither chip covers, so the lit chip, the picker and the saved day always agree (#90); the picker shows whenever the day is neither chip's. `@expo/ui` gotchas (SDK 57): a `Host` inside a `flexWrap` row loses its place, so it sits beside whatever may wrap, never within it; the community `datetime-picker` drop-in only matches its content vertically and collapses in a row, so use `Host matchContents` around the SwiftUI view; an inline `Host` needs `ignoreSafeArea="all"` (as Expo's own community wrappers pass), or its content rides up by the keyboard's inset while a sheet's keyboard is up. `Host`'s `seedColor` takes `colors.tint` as it is: Expo's colour conversion resolves a `DynamicColorIOS` per appearance, so no hex is needed.
- Styling comes from `src/ui/theme.ts`, the only file holding colour values (the app icon and splash repeat a few, below, and the Web view mirrors them in `web/src/app.css`): a warm ground from Ecru's hue (spec #61) for `background`, `surface` and `raised`, a warm `secondaryLabel` in light mode (iOS's reads 3.3:1 on a light ground), the raised surface for sheets (spec #84), iOS semantic colours for fills, separators and the other labels, and the palette (ticket #34): Dark Medici Blue as the tint, Ecru as `tintSoft` (never behind tinted text: 2.46:1), a paled tint as `tintFill` behind a picked chip, under ink (spec #92), Olive Ocher as the sun, and the care hues muted from the palette (slate blue, khaki, a softer Hay's Russet; prototype/care-icons, variant D) so the filled care icons don't read as emoji, each but Olive Ocher a `DynamicColorIOS` with a dark shade picked for dark mode's contrast. All follow light and dark mode natively. The status colours are the palette's too, quieter than iOS's red and orange: `caution` (overdue care, toxicity) is Hay's Russet, `dueToday` is the tint, each word-only (no coloured edges or borders) and at least 4.5:1 for a status line; `danger`, iOS's systemRed in its light Increase Contrast shade (the default reads 3.5:1 on a card, ticket #30), is for destructive actions only; the navigation theme, in hex and picked by `useColorScheme()`; the grounds (spec #61): a screen sits on `background`, a group of rows or a banner is flat on it in `surface`, and what you act on (Today's first card, the most Overdue, and the Plant screen's tiles; Today's other cards are outlined on the surface, spec #84) is raised by `useRaised()`, a warm two-part `boxShadow` in light mode and the lighter `raised` surface in dark mode, so a raised view never sets `overflow: 'hidden'`, which on iOS clips its shadow; Settings' Form sits on the ground through `scrollContentBackground('hidden')` and `background`, its rows on the surface through each Section's `listRowBackground`; three radii, `radius.surface` (24) for a surface on the ground, `radius.inner` (12, the surface's less its 12 pt padding) for a photo or a control (the Garden grid's photos, on the ground, take `radius.surface` through `PlantPhoto`'s `radius`), `radius.pill` for chips, badges and anything round, and no screen sets a radius literal (the Form keeps SwiftUI's own); the type scale, spacing steps, target, pressed and grouped-list styles, and `accessibilitySize`, the font scale past which a row of controls stacks. The type (spec #57) is Nunito Sans, with Young Serif on the titles, embedded by expo-font's config plugin in app.json (a static face per weight; adding one takes a prebuild): `font.*` holds the faces as family plus weight plus style, since React Native finds a face by all three and a PostScript name as the family drops the italic; `text.*` holds the six steps, its table above it; `headerFonts` goes in every Stack's `screenOptions`. No screen sets `fontWeight` or `fontFamily` itself; it spreads `text.*` or `font.*`. React Native draws text black in either appearance, so every `Text` takes a `text.*` style or a colour from `colors`; SwiftUI views (Settings' Form, the date picker) draw with SwiftUI's own type and colours, their `Host` given `seedColor={colors.tint}`. Icons are Phosphor's (spec #57), drawn by `Icon` (`src/ui/Icon.tsx`), which names them by meaning (`water`, `pest`, `next`…), imports each from its own file (`phosphor-react-native/src/icons/…`, since the package's index is all of Phosphor and Metro doesn't tree-shake it) and hides them from VoiceOver; care types draw filled in their hue, every other icon Regular (#55, variant D on `prototype/quiet-icons`), and an icon whose words already say it is left out (the toxicity badge and the pet warning are words only). The Garden is a grid of photos (spec #61, ticket #65), two columns sized from `useWindowDimensions`, one at `accessibilitySize`; each cell a Pressable button VoiceOver reads as its name and scientific name; `PlantRow` stays for Archived. A plant without a photo shows its initial in Young Serif on a paler Ecru, `photoPlaceholder` (`PlantPhoto`, `Initial` in `src/ui/Photo.tsx`). A Care Event type's icon and hue live in `CARE_COPY`, and `CareSymbol` draws them (`src/ui/CareEvent.tsx`). The tab bar takes SF Symbols or images only, so its icons are template PNGs in `assets/tabs` (1x to 3x, selected and not), rendered from `@phosphor-icons/core` at 26 pt; Today's ⋯ menu is SwiftUI's and keeps SF Symbols (`systemImage`). The app's words for care and dates (`CARE_WORDS`, `plural`, `dayLabel`, `tileValue`…) live in `src/ui/words.ts`, which imports nothing from React Native so the Web view says the same. Every `Pressable` shows a `pressedStyle` (Today's check circles fill with their tick instead, and the Garden grid's cells sink on a spring through `PressSink`) and is a 44 pt target, with `hitSlop` where it's drawn smaller. `hitSlop` reaches only as far as the nearest ancestor that clips (`overflow: 'hidden'`, a ScrollView), so that ancestor needs the padding; a header button needs the 44 pt as its own size (`target`), since UIKit routes touches to header items, and so does the view inside a SwiftUI `Menu` (Today's ⋯), since SwiftUI takes its touches. A screen or list with nothing to show shows `EmptyState` (`src/ui/EmptyState.tsx`): an icon, a title, one line where the title needs one and, where one applies, the action that fills it. Motion (#55, variant C on `prototype/motion`) lives in `src/ui/motion.tsx`: springs where something arrives or settles (Today's check, the rest of a list moving into place, the hero photo settling from a slight zoom, a sheet's parts rising one after another, the undo toast), short fades where something leaves. Under Reduce Motion (`useReducedMotion`) everything only cross-fades, its fades marked `ReduceMotion.Never` since they move nothing, and the haptics stay. One care ticked is a light impact (`tickHaptic`); Success (`taskHaptic`) is for a task done, Log all and the log sheet's Save. Sheets and pushes stay native. An `Animated.ScrollView` that drives scroll motion (`useScrollOffset`) takes no `scrollEventThrottle`: Reanimated's default is 1, and the Plant screen's old 32 held its hero to 30 updates a second under 120 Hz scrolling; what JavaScript needs from the scroll comes through `useAnimatedReaction` and `scheduleOnRN`, only when it changes (the bar's title). Reanimated's `IOS_SYNCHRONOUSLY_UPDATE_UI_PROPS` static flag is on (`reanimated.staticFeatureFlags` in package.json, read at `pod install`, so changing it takes a native build): transforms and opacity, such as the hero's drift, stretch and bar fade, go straight to the view each frame instead of through a shadow-tree commit, which made them judder on the owner's 120 Hz iPhone (2026-09-28). Fabric's hit-testing doesn't see those transforms, so a control that moves by an animated transform is tapped where its layout puts it. Screens animate changes with Reanimated's layout animations and `withSpring`/`withTiming` only: React Native's `LayoutAnimation` aborted the app once (SIGABRT in `LayoutAnimationDelegateProxy`, a sheet closing during Today's refresh).
- The app icon and the splash (ticket #29) are drawn from `assets/icon.svg`, whose header names each PNG beside it, what it's for and its two fills. Those fills, and the splash's backgrounds in app.json (`#000000` in dark mode), repeat colours from theme.ts, since neither file can import them. `ios.icon` names the light, dark and tinted icons. Expo flattens a transparent light or tinted icon onto white, so only the dark one is transparent and the tinted one is white on black. The splash is the `expo-splash-screen` config plugin's, and expo-router hides it once the first screen is ready, so no code calls it. Changing either takes a prebuild and a native build. Judge the splash on a signed Release build: a Debug build holds it while Metro bundles and shows white for a moment after it, and iOS won't draw the launch screen of an unsigned simulator build (`CODE_SIGNING_ALLOWED=NO`; SpringBoard logs `Security error -67056`), zooming a black screen instead, so sign one with `codesign --force --deep --sign -` first.
- Schema changes: edit `src/db/schema.ts`, run `npm run db:generate`, review the new SQL in `drizzle/`. Migrations are forward-only; the schema version is SQLite's `PRAGMA user_version`. An Import runs them on an older Export's rows too, in a database holding nothing else (no Species catalog), so a data migration must not depend on the catalog (ADR-0002). Then `npx jest --clearCache`: the SQL is inlined into `drizzle/migrations.js` at transform time and jest caches the result, so an edited or regenerated migration otherwise runs stale in tests ("no such table").
- Species catalog changes: edit `scripts/species/curated.json` (IDs are Wikidata QIDs, append-only, ADR-0004), bump its `version` whenever species content changes, run `npm run species:build`. Pet toxicity is `true`, `false` or `null` (unknown, no badge), by the rule in `scripts/species/build.ts`'s header: a reference listing the Species or its genus, or a relative sharing its toxic principle; never by guess (#53). Never hand-edit `assets/species.json` or `assets/species-index.json`; the app reseeds the read-only `species` table when the bundled version is newer. The build also writes Identify's name index (ADR-0007), `assets/species-index.json`: each Species' names and GBIF keys (Wikidata's P14607, else GBIF's match on its P225 name, plus that taxon's GBIF synonyms), and the `aliases` in curated.json, a Pl@ntNet or GBIF name, or a second common name the Species search falls back to (only one no other catalog Species goes by), → QID. A Species' own name beats another's synonym; a name two Species claim alike fails the build, naming both QIDs, until an alias settles it. The index is its own asset, never columns in `species`: a change to it needs no migration, reseed or `version` bump, and the Web view never loads it. A new Species also needs its Care Guide entry in `assets/care-guides.json` (ADR-0008, spec #48): a Care Profile, care notes only where it differs, and a Fun fact in our own words with its Wikipedia `funFactSource`; hand-edited and reviewed, not built, with its rules (references resolve, no days, weeks or months in profile or care-notes text) enforced by `src/core/careGuide.test.ts`.
- `ios/` and `android/` are generated (CNG). Never edit them; configure native behaviour in `app.json` and config plugins.
- Our own native code is a local Expo module under `modules/` (ADR-0010), autolinked like a package: `modules/photo-focus` (Swift, iOS only) is `findFocus(uri)`, the centroid of Apple Vision's attention saliency heat map over a prepared JPEG, returning its Focal point (`Focus`, `src/core/photos.ts`). A module needs `expo-module.config.json`, a podspec and its Swift. Changing it takes a prebuild and a native build. The simulator's Vision can't run the model (it throws, and with `usesCPUOnly` returns the same point for every photo, so the module leaves it to throw), so check points on the iPhone or with a Mac command-line tool over the same request, and check framing on the simulator by stubbing `findFocus` from the inspector. Picking a photo is `usePhotoPicker` (`src/ui/Photo.tsx`): its `choose` picks, prepares and finds the point (the centre where Vision finds none), then its `framing`, which the screen renders, is Frame photo, a full-screen `Modal` (a pageSheet's pan cancels the marker's drag a few moves in) where the point is dragged or tapped, with the Garden square and the hero previewing it; Use Photo hands `Picked` on, Cancel deletes the prepared file. It's the only place a point is set by hand: no Reposition later (spec #67). Drive it on the simulator with an XCUITest `press(forDuration:thenDragTo:)` on the element labelled "Photo, framed where the plant was found". `useFindMissingFocus` (same file), from the root layout, runs `findMissingFocus` once at launch: a point for each live photo without one (`photosWithoutFocus`, `setPhotoFocus`), one at a time, a failure left for the next launch. Every frame of a photo centres on its point through core's `framePosition`: on the phone `coverStyle` (`src/ui/Photo.tsx`) sizes and offsets the `Image` inside its clipping frame (`PlantPhoto`, the hero), and on the Web view `objectPosition` (`web/src/icons.tsx`) gives the `<img>` its `object-position`. A read that shows a photo returns `focus` beside `photo`, through `focusColumns` and `toFocus`.
- iOS 27 refuses to launch an app built with its SDK unless the app adopts the UIKit scene life cycle (the crash names `UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption`). SDK 57's template doesn't, so `plugins/withSceneLifecycle.js` backports SDK 58's wiring: a scene manifest naming Expo's `EXExpoAppSceneDelegate`, and an `AppDelegate` that leaves the window and React Native's start to it. Delete the plugin when upgrading to SDK 58.
- Native modules (sqlite, notifications, sharing, crypto, secure-store) need a dev build, not Expo Go: `npm run ios`.
- expo-notifications' config plugin runs on every prebuild without an `app.json` entry (one of Expo's automatic plugins) and adds an `aps-environment` entitlement, so the signing team needs the Push Notifications capability, which automatic signing adds. The app schedules local notifications only and never registers for push.
- `react-dom` is pinned to the same version as `react` only so npm can resolve expo-router's transitive web peers (there is no web target, ADR-0001). Removing it reintroduces an `ERESOLVE` on install; bump it together with `react`.
- Adding a root dependency: `npx expo install` can write `package.json` and then fail npm's resolution (observed 2026-09-22: `ERESOLVE` on `react-native-worklets`, a peerOptional of `expo-modules-core`), leaving `package-lock.json` untouched. Check `git diff package-lock.json`; never fall back to `--legacy-peer-deps`. `expo-modules-core` itself is imported as the transitive `expo` pins, not declared, for this reason.
- Dynamic Type while the app runs: React Native (0.86, Fabric) never measures text again when the text size changes, so views keep the old size's heights (Today's cards stood tall with small text). The root Stack in `app/_layout.tsx` is keyed by `useWindowDimensions().fontScale`, so every screen is drawn anew; expo-router keeps the navigation state, so the open screen stays open. Check it by launching at an accessibility size and switching to the default with `simctl ui content_size` while the app runs.
- Accessibility (ticket #30): every section heading, sheet title, `EmptyState` title and the Plant screen's name is a `Text` with `accessibilityRole="header"`. An icon beside its own words (`CareSymbol`, the archive box) is hidden from VoiceOver, which `Icon` does itself; an icon-only control labels its `Pressable`. SwiftUI views are labelled through their modifiers, never a React Native child: Today's ⋯ is `Menu` from `@expo/ui/swift-ui` with `accessibilityLabel`, since the community `MenuView` drop-in left SwiftUI's button unlabelled. Segmented choices are `Segmented` (`src/ui/Form.tsx`), a SwiftUI segmented `Picker` at `controlSize('extraLarge')`, 47 pt; its labels, like UIKit's, don't grow with Dynamic Type. A header's text button is `TextButton header`: 44 pt, and capped with `maxFontSizeMultiplier={1}`, since UIKit's header title never grows; a modal form's Cancel and confirm (New plant's, Edit plant's) are iOS's own bar buttons instead (`unstable_headerLeftItems`/`unstable_headerRightItems`, experimental in SDK 57), so they take iOS 26's glass and padding: Cancel plain in ink (`MODAL_FORM`, app/_layout.tsx), the confirm prominent in `colors.confirm`, Medici's light shade in both modes, under iOS's white label (`confirmItem`, src/ui/Form.tsx; spec #92). iOS blends a prominent item's label with the glass, so a dark label on dark mode's paler tint read 1.9:1; measure a header item's contrast from a screenshot, not from its colours. React Native scales every text size by body text's multiplier (3.57 at the largest size), past iOS's own Title 2 (22 to 56 pt), so a sheet's title and an `EmptyState` title take `maxFontSizeMultiplier={TITLE2_MAX_SCALE}` (theme.ts), and rows that break words at accessibility sizes stack (`accessibilitySize`), as the date picker's row and the Care Event sheet's title do. The compact `DatePicker` is 33 pt tall, which neither `controlSize` nor `frame` changes, and reads as "Date Picker" after the label above it. While a screen reader runs, the undo toast (`useUndoToast`) stays until Undo, the next toast or its screen losing focus, since VoiceOver can't reach the end of a screen within its 4 s (ticket #33).
